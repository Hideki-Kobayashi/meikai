# meikai（明快）

伝える要点と情報の順序を整理し、具体的で分かりやすい日本語を書くためのAgent Skillです。

記事、説明文、告知、投稿、スライドなどを新しく作るときに使います。
題材やメモから何を伝えるかを決め、タイトル・見出し・本文に情報を配置します。

## どんな文章を目指すか

「差が広がる」「変化が起きる」といった言葉だけでは、何について何を伝えているのか分からないことがあります。
meikai は、読み手に必要な対象や関係を具体的に書き、細かな説明は本文に配置します。

例えば、問い合わせ対応の改善を検討する資料では、次のような見出しを生成しました。

> 個別調査の問い合わせは減っていない

何が課題なのかを見出しで示し、本文で減った問い合わせの種類や、まだ把握していない対応時間を説明しています。
[入力と出力の実例](examples/inquiry-improvement/output.md)を掲載しています。

## インストール

skills CLI を使う場合は、次のコマンドでスキルを選択して導入できます。
Node.jsとnpxが必要です。

```sh
npx skills add Hideki-Kobayashi/meikai --skill meikai
```

手動で導入する場合は、[skills/meikai](skills/meikai) フォルダーを、利用するエージェントのスキル用ディレクトリにコピーしてください。
Codexでプロジェクト内に置く場合は `.agents/skills/meikai/` が配置先の一例です。

## 使い方

導入後、材料と一緒に依頼します。

```text
$meikai を使って、以下のメモから社内向けの告知を書いてください。
読み手は全社員です。タイトルと本文を作ってください。

（ここにメモを貼る）
```

```text
meikai を使って、以下の資料からスライドを作成してください。
読み手は問い合わせ対応の責任者と担当者です。
会議の目的は、実績を共有し、改善方針を決めることです。
表紙と目次を含め、全体で説明が完結する資料にしてください。

（ここに資料を貼る）
```

読者、目的、掲載先、長さが分かっている場合は、一緒に伝えると判断の助けになります。
すべてを指定する必要はありません。
通常は完成文を返し、中心となる内容を決めるために情報が必要な場合だけ質問します。

スキルの呼び出し表記や自動選択の動作は、利用するエージェントによって異なります。
meikai は名前での指定に加え、説明文に合う依頼での自動選択も許容しています。

## 文章を作る手順

1. 目的と読者を把握する。
2. 中心となる内容と優先順位を決める。
3. 読み手が理解できる順序で情報を配置する。
4. 対象や関係が具体的に分かる本文を書く。
5. 本文で伝える内容に合うタイトル・見出しを付ける。
6. 意味、条件、主張の強さが材料と一致しているか確認する。

文字数や禁止語で一律に制限せず、必要な具体性を保ったまま簡潔に書くことを目指します。
詳細は [SKILL.md](skills/meikai/SKILL.md) にあります。

## 対応範囲

meikai の本体はMarkdownの指示書です。
検査スクリプトや外部APIへの依存はありません。

- 文章の内容と表現を組み立てます。既存文の校正やAIらしい表現の除去だけを目的とするスキルではありません。
- スライドファイルや文書ファイルを生成する機能は含みません。ファイル作成には、利用環境側のツールや別のスキルが必要です。
- 事実確認を自動で保証するものではありません。材料にない事実を作らないよう指示していますが、重要な内容は出力を確認してください。

## 試用と限界

Codexで、架空の問い合わせ対応事例から6枚のスライドを作る試用を行いました。
別セッションでスキルあり・なしを各1回生成して比較し、利用者はスキルありの言い回しを好みました。

スキルなしでも情報の整理や断定の回避はできており、全体の品質に明確な優劣があるという結果ではありません。
モデル・設定・ほかのスキルの影響を統制した比較や、繰り返しの評価は行っていません。
別の題材や環境でも同じ効果が得られるかは未確認です。

例のスライド作成には、文章生成以外のプレゼンテーション作成機能も使っています。
見た目やファイル生成までmeikai単体の効果とはしていません。

## 着想元と参考

- [いる科氏の投稿](https://x.com/iru_cection/status/2121705510319825086)：タイトルを作る前に伝えたい内容と優先順位を整理し、曖昧な一語に文脈を詰め込まないという考え方。
- [中嶋よしふみ氏の投稿](https://x.com/valuefp/status/2121735384728232421)：重要なキーワードをタイトルに残し、詳細を本文に配置するという考え方。
- [yomiyasu](https://github.com/nanaism/yomiyasu)：GitHubでのスキル配布方法と、使用例・検証範囲の説明を参考にしました。

meikai は、投稿の考え方を文章の新規生成へ応用して独自に手順化したものです。
投稿本文やyomiyasuのスキル本文・スクリプトを転載したものではありません。
各作者による監修・推奨を示すものでもありません。

## 改善への参加

気になる出力があれば、公開できる入力、実際の出力、期待する結果、利用したモデル・環境を添えてください。
機密情報や個人情報を含む材料は、架空の内容に置き換えてください。
